## 同步内容

同步内核驱动、共享 UAPI、管理器、`ksud` / `ksuinit`、必要资源和许可证。多数管理器路径变化来自官方 `com.resukisu.resukisu` → `org.bakasu.bakasu` 源码包名迁移，默认 APK 安装包名仍沿用官方配置。

与旧集成基线相比，主要更新包含：

- 管理器扫描、管理器列表和 SELinux 策略访问的 RCU 修复。
- SELinux `avtab` 迭代、删除长度和扩展权限更新修复。
- 增加 UAPI 5 的 `EVENT_SERVICES` 事件，区分 service 阶段首次执行和重复调用。
- 启动脚本等待期限、软重启进程等待、boot 解析失败处理等 `ksud` 更新。
- 管理器启动卡住、WebUI 无法打开、模块快捷方式、主题初始化与导航的更新。

上游新增 RISC-V 路径属于源码同步内容；此次目标仍是 ARM64，不代表 RISC-V 或其他机型已经测试。沿用既有源码集成范围，不导入上游 `.github` 自动化或个人编辑器配置，也不更换本仓库工作规则。

## 必须保留的本地适配

1. **源码直接集成版本读取**：`kernel/Kbuild` 继续支持没有独立 `.git` 的 `KernelSU`；管理器和 `ksud` 也读取同一版本文件，避免错误使用外层内核仓库的标签和提交数量。
2. **SELinux 5.4 状态锁导出**：保留 `ksu_selinux_status_lock` 及 `EXPORT_SYMBOL_GPL`，对应本仓库 `security/selinux/selinuxfs.c` 的调用。未把上游 `static` 定义覆盖回来。
3. **既有管理器兼容**：保留 MKSU、RKSU、SukiSU-Ultra 的既有签名，以及它们在多管理器列表中的原索引顺序。BakaSU 的签名值与原 ReSukiSU 一致；未新增原先不信任的签名。
4. **模块标识兼容**：在官方 `BAKASU=true` 环境标识之外继续提供 `KSU_SUKISU=true`，防止既有模块的旧项目检测失效。
5. **现有 setup 脚本保护**：保留本仓库的集成保护逻辑，只更新官方仓库地址；此次没有执行该安装／清理脚本。

设备 defconfig、SUSFS 的外层源码和 Hook、ReKernel-X、统一修复模块、`scripts/ak3`、内核命名规则均不属于本次改动范围。开始前已有的五个 Windows 路径删除状态必须保持原样。

## UAPI 和使用边界

`uapi/supercall.h` 从 UAPI 4 升为 5，新增 `EVENT_SERVICES=4`，现有 ioctl 编号和结构体布局沿用官方定义。内核返回首次执行／跳过的结果，配套 `ksud` 据此避免重复启动模块 service 脚本。

官方 `rc3 / 35171` Release 的 UAPI 仍为 4；35218 管理器及其 `ksud` 使用 UAPI 5。正式启用和实机验收前必须核对内核与运行 `ksud`，不能只看 APK 版本；也不得屏蔽 UAPI 不匹配检查来伪装兼容。

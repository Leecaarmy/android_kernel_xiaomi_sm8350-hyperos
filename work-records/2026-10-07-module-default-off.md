# 统一修复模块新安装默认关闭

日期：2026-10-07（Asia/Shanghai）。

类型：非内核模块行为修正。

源码基线：`dynamic` / `f20758ef80ac78338090faa38a60171ccaeed217`；工作树已有未提交 RTC 修复，本次在该状态上最小修改默认值，没有合并或覆盖其他改动。

## 用户要求与原因

用户明确要求新安装时所有修复开关保持关闭，由用户根据对应错误日志及建议自行选择开启。

原配置中的 ATFWD、traced 默认值为 `1`，运行时读取配置失败时部分功能也会返回 `1`。安装器还会保留已打包的 ATFWD 策略覆盖；traced 关闭路径可能恢复 ROM 属性，即使本模块此前从未启用过该修复。这些行为不符合新安装默认保持关闭的要求。

## 最小修改

- `modules/atfwd_seccomp_fix/config/atfwd_enabled`、`traced_enabled` 改为 `0`；GNSS、TCM、RTC 的默认值原本为 `0`，保持该值。
- `control.sh` 的配置缺失、无效或读取失败回退统一为 `0`；合法用户选择 `1` 仍保留。
- `customize.sh` 先初始化全部五个开关为 `0`，再保留升级前合法的 `0/1` 选择；新增及无效旧配置保持关闭。
- 安装器在 ATFWD 关闭时移除单个策略覆盖文件，保留资产中的原策略和修复策略供用户以后启用。
- traced 关闭且没有本模块原属性记录时直接返回，不读写通道属性、不重启服务。
- 模块说明、安装提示和 WebUI 标明全部默认关闭；工作规则新增同一要求。
- 保留现有只读日志建议：对应错误存在时建议开启，未发现时暂时无需开启，读取失败时提示无法判断；仅用户手动操作可改变开关。
